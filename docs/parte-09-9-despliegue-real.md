# Parte 9.9 — API publicada e instalador conectado

**Estado al 7 de noviembre de 2026:** API publicada en Azure App Service Linux B1, instalador Windows x64 generado e instalado en el equipo de desarrollo. La ruta `/ready` comprobó la conexión de la identidad administrada a SQL. El usuario completó el inicio de sesión Entra y abrió el inventario en el escritorio. Con la API detenida, el escritorio guardó una entrada y una salida de prueba en cortes separados; ambas se confirmaron al reconectar y Azure SQL mostró el stock y cupo actualizados. La instalación en una segunda PC funcionó tras seleccionar la identidad Microsoft autorizada con `0.1.4`. Se verificó lectura y escritura cruzada entre sesiones Windows con stock restituido a 4. La API subió y descargó un adjunto privado en Blob con hash idéntico. Un equipo ficticio fue revocado y la API bloqueó su descarga y re-registro. Falta la desinstalación real.

ACR Build está bloqueado por la suscripción (`TasksOperationsNotAllowed`), así que la imagen se compiló con Docker local y se subió al registro privado. App Service F1 no pudo crearse por cuota cero; B1 sí se creó. La URL administrada de App Service evita comprar un dominio.

## Seguridad y datos

- La API usa la identidad administrada para extraer la imagen (`AcrPull`), acceder al contenedor privado (`Storage Blob Data Contributor`) y autenticar Azure SQL. En SQL se creó un usuario contenido con `SELECT`, `INSERT` y `UPDATE` en `jm`, más `DELETE` solo sobre las líneas de factura. No se configuraron credenciales SQL ni claves Storage en la API.
- SQL conserva el acceso de red público con las 13 IP de salida actuales de App Service permitidas individualmente. No se habilitó la regla amplia `0.0.0.0` para todos los servicios Azure. Si cambia el plan o las IP de salida de App Service, revisar las reglas `jm-api-01` a `jm-api-13`.
- La clave privada RSA 3072 del permiso offline se generó en el perfil local del operador (`%LOCALAPPDATA%\JorgeMotorsDeployment\offline-grant-private.pem`) y se configuró como valor protegido de App Service. Su clave pública está en `desktop/auth-config.json` y en el instalador. **Conservar una copia segura de la clave privada**: reemplazarla invalida los permisos offline ya emitidos.
- El instalador no contiene contraseñas SQL, tokens ni la clave privada. `desktop/auth-config.json` está ignorado por Git. La API devuelve `401` para `/auth/me` y `/sync/devices` sin token.

- Azure SQL quedó `Online` tras consultar y aplicar migraciones; hay 11 versiones en `dbo.jm_schema_migrations` y un principal para la identidad de la API. La base puede volver a pausarse según su configuración serverless.

- El usuario confirmó que el acceso en la segunda PC abrió el inventario con la cuenta correcta. En el portal Entra, el evento interactivo del 7/11/2026 a las 20:14:23 UTC corresponde a `Jorge Motors - Cliente local - Demo` y al recurso `Jorge Motors - API - Demo`. - El 10/11/2026 se comprobó de nuevo el selector de Entra y estaba en `Habilitado (recomendado)`. No se modificó desde este proyecto durante esa comprobación. El usuario desea usar solo la MFA de Entra ID Free. Esta configuración protege al directorio, pero Microsoft decide cuándo solicitar otro factor y puede reutilizar una sesión que ya lo satisfizo. En una prueba de acceso a Jorge Motors ese mismo día, Microsoft abrió directamente el inventario sin desafío MFA. Por tanto, el requisito de solicitar MFA en cada conexión con excepción para equipos administrados y aprobados **no está cumplido**. Esa política requiere Acceso condicional (Entra ID P1); no debe simularse con `prompt=select_account` ni con un aviso local que pueda eludir la API.
