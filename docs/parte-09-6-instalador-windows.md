# Parte 9.6 — Instalador y desinstalación de Windows

**Estado al 7 de noviembre de 2026:** instalador NSIS de un clic compilado con configuración real de Entra/API e instalado en el equipo de desarrollo. Se comprobó el inicio de sesión, la sincronización offline y las actualizaciones hasta `0.1.4` sin perder datos. En una segunda PC, la versión anterior eligió una cuenta Microsoft sin perfil; `0.1.4` permitió elegir la cuenta autorizada y abrió el inventario. Pendientes: ciclo offline completo en esa PC, desinstalación real y firma de código.

El paquete `Setup.exe` instala Electron, React y SQLite para el usuario actual, sin pedir Node, pnpm, SQL Server ni terminal en el equipo de destino. Crea accesos directos de escritorio y menú Inicio y registra el desinstalador de Windows. La aplicación sirve el frontend desde un puerto local disponible. La primera autenticación Microsoft y descarga inicial requieren internet. No se necesita un dominio propio: la configuración puede usar la URL HTTPS administrada de la API.

Los datos de cada usuario de Windows viven en `%APPDATA%\Jorge Motors`, fuera de los archivos del programa. Una actualización conserva ese directorio. En la desinstalación interactiva se muestra el número de operaciones pendientes y rechazadas. El usuario puede conservar los datos, exportar una copia a otra carpeta, eliminarlos completamente o cancelar. El borrado pide una segunda confirmación; la desinstalación silenciosa conserva datos. La copia incluye la base local, el identificador del equipo y material cifrado por Windows: es un respaldo para ese usuario/equipo, no una migración automática a otra PC. Desinstalar no modifica Azure SQL ni los usuarios de Entra.

Para construir un release real se necesita `desktop/auth-config.json`, a partir de `desktop/auth-config.example.json`, con `tenantId`, `desktopClientId`, `apiClientId`, `apiBaseUrl` y la clave pública RSA del permiso offline. Esos valores son públicos; el instalador no debe contener credenciales SQL, secretos de aplicaciones ni claves privadas. El comando `pnpm run dist` valida que no sean marcadores de ejemplo, compila el frontend y crea el instalador en `desktop/release`. La construcción usa una carpeta temporal de ruta corta porque el compilador NSIS no acepta las rutas largas del proyecto dentro de OneDrive y `pnpm`. Se genera también un SHA-256 del ejecutable.

El icono de Windows `desktop/build/icon.ico` reproduce el recuadro marrón con **JM** blanco de la interfaz. `desktop/scripts/generate-icon.ps1` lo genera en tamaños de 16 a 256 píxeles. `electron-builder` lo aplica al ejecutable, instalador y desinstalador; la ventana Electron también lo declara expresamente. La versión `0.1.3` establece `pe.jorgemotors.inventory` como identificador del proceso y fija el icono del grupo de la barra de tareas con `setAppDetails`, usando el recurso del ejecutable. El release verifica la estructura del `.ico` para impedir que vuelva a aparecer el icono predeterminado de Electron.

La primera prueba de compilación creó un `Setup.exe` **sin configuración real** y no se distribuyó. La [Parte 9.9](parte-09-9-despliegue-real.md) registra el instalador actual con URL cloud y clave pública reales, instalado en el equipo de desarrollo. Antes de entregarlo a otras máquinas faltan firma de código, ambas modalidades de desinstalación y la prueba en un Windows limpio. La [Parte 9.7](parte-09-7-continuidad-offline.md) reemplaza el vencimiento inicial de 24 horas.

**Verificación actual:** instalación y actualización silenciosas en el equipo de desarrollo con salida `0`, acceso directo apuntando al ejecutable `0.1.4`, icono **JM** extraído del instalador y ejecutable, y captura de la ventana con el mismo icono en la barra de título. El usuario confirmó que la barra de tareas también muestra **JM**. El identificador de equipo se conservó y la base local mantiene las dos operaciones sincronizadas. La desinstalación interactiva aún no se ha ejecutado.
